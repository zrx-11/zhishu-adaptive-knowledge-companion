# 参考过的开源项目

动手之前把这些项目翻了一遍。下面记的是真正用上的部分，以及它们没做而我们做了的部分。链接放在最后。

## book-to-skill（virgiliojr94）

它把两件事拆得很干净：一个确定性的 Python 抽取器负责把文档变成干净文本加元数据，另一段由 agent 按规格把文本编译成结构化技能。产物是章节索引、术语表、模式库、速查表，agent 按需加载，不把整本书塞进上下文。

我们的抽取器和 manifest 基本照着这个思路来。区别在服务对象：book-to-skill 面向 agent 调用，人不需要读；点化必须产出人能读、能练的东西，所以章节精讲、测验、抽认卡是硬性要求。

## book-to-visual-companion（sanjaygupta-professional）

形态是书变成可视化学习站，Mermaid 概念图、章节图、学习路径、交叉链接，用 Astro/Starlight 构建。

图和路径的做法我们留下了，构建工具链没有。它要求 Node 环境，产物是多文件站点；我们要的是双击能开的单文件，所以把渲染和路由都塞进了 HTML 里。代价是图在离线时会降级成源码，这一点在文档里写明了。

## book-reader

一个阅读器形态的项目，目录树、章节导航、阅读进度。导航和进度的交互我们直接借鉴了，另外加了深色模式和跨书搜索。

## Book-to-Course

把书拆成"模块 → 课 → 检查点"的课程结构。我们的学习路径用了同样的骨架，每一步必须挂一个可验证的检查点，没通过不放行。

## repo-mastery

核心是学、测、复习的循环。这套循环体现在每章的自测题、综合测验和抽认卡上，复习锚点则是"隔几天回来能一句话复述"的那几条。

## cangjie-skill

技能工程化的参考：frontmatter 只留必要字段、渐进披露、脚本和参考资料分开放。本仓库的目录结构按它来。

## 我们多做的一点东西

这四件事在上面几个项目里基本找不到，是这次真正新增的：

1. 多本书收进一个 `index.html`，带书切换、跨书总览、全局搜索、分书进度。
2. 交付粒度可选：`final` 只要成品，`full` 连中间产物一起给，两种都附说明文档。
3. 默认就能挂 GitHub Pages，`.nojekyll`、相对路径、中文文件名这些坑在生成阶段就处理掉。
4. 验证脚本化。用真浏览器跑三十多项交互检查，还能拿去复测解压后的交付包，而不是靠肉眼点几下。

## 看过但没采用的

- 纯摘要工具：解决的是"这本书讲了什么"，跟"怎么学会"不是一回事。
- 纯 RAG 方案：切块检索适合查句子，不适合按顺序学。点化里只保留了全文搜索这一个检索功能。
- 需要本地起服务的方案：对"下载下来就能用"这个诉求不友好。
