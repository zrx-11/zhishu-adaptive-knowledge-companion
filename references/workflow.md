# 点化工作流（分阶段操作细节）

执行主流程前必读。每阶段的输入、动作、产物、检查点如下。

## Phase 0 — 输入与参数确认

**输入**：用户提供的书籍文件/文件夹/链接 + 目标描述。

**动作**：
1. 清点文件：路径、格式、大小；识别「单书」还是「一类主题的多书/资料集」。
2. 确认参数（能推断就推断，不重复追问）：
   - **学习目标**：入门了解 / 系统掌握 / 能应用（默认系统掌握）
   - **受众基线**：默认零基础
   - **语言**：默认与用户对话语言一致
   - **交付模式**：`final` 仅最终产物 / `full` 最终+中间产物（**必须确认**；用户有长期偏好则沿用）
   - **部署**：是否要放入 GitHub 仓库并部署 Pages（要则生成 `.nojekyll` 与 README 部署说明）
   - **目录与 slug**：每本书一个 `NN-书名/` 子目录；`manifest.slug` 只用小写字母、数字和连字符，定下来之后不要再改——它同时是路由 key 和进度存储的命名空间
3. 文件不可读时先修路径/换下载方式；仍失败则索要有效文件，禁止猜内容。

**检查点**：书籍清单、交付模式、部署需求三项明确。

## Phase 1 — 文本抽取与结构拆解

1. `python3 scripts/extract_text.py --check` 看解析器；再 `python3 scripts/extract_text.py <files...> --out <root>/<书目录>/_work/raw/`。
2. **数学/扫描版 PDF**：若出现 `cid:`、□、公式丢失，弃用文本，改用 Read 按页读图（必要时用 PyMuPDF 导出页面 PNG 存 `_work/`），逐页核对公式与记号。禁止用乱码硬撑。
3. 结合官方目录/前言/索引与正文标题行，产出**结构地图**（部/章/节、附录、索引）。
4. 按章切分语料为 `_work/raw/chNN.txt`，供按需精读。

**检查点**：结构地图与真实目录一致；每章语料非空；扫描版走读图路线。

## Phase 2 — 概念与心智模型抽取

逐章精读后产出：
1. **核心论点**：全书在回答什么问题、作者主张、论证主线（2~3 句）。
2. **概念清单**：术语 + 白话定义 + 首现章节 + 难度。
3. **依赖图**：前置/后续关系，标跨章依赖；必须无环。
4. **难点地图**：零基础视角每章最难的 1~3 点及缺失的前置。
5. **心智模型/框架**：作者反复使用的分析框架、决策规则、反模式（存入 `patterns.md`）。

**检查点**：概念覆盖全书；依赖图无环；每个前置缺口在学习路径中有补讲。

## Phase 3 — 零基础学习内容生成

按 `references/templates.md` 逐章生成：学习目标、一句话核心、零基础讲解、图示、类比（注明边界）、实例（可验证）、常见误解、自测题、复习锚点；并写跨章概念页。写作遵循 `references/pedagogy.md`。

**检查点**：硬性质量门（三件套≥2、自测题带答案、术语首现即定义）。

## Phase 4 — 学习路径与记忆系统

1. **学习路径**：按依赖图拓扑排序；把前置缺口补讲插入路径；每步写「目标 + 读哪章 + 检查点」。
2. **测验**：各章自测题 + 综合题 + 最终检验（项目式/综合任务）。
3. **抽认卡**：每章 5~10 张（正面只放问题）。
4. **术语表**、**模式库**、**速查表**。
5. 多书场景：概念合并去重（标出处）、统一依赖图、按主题而非书序排路径、冲突口径用对比块并存。

**检查点**：路径拓扑序；答案与讲解一致；卡片正面不含答案；多书概念无重复无冲突。

## Phase 5 — 单书组装

1. 交付目录结构（每本书一个子目录，建议 `NN-书名/`）：
   `SKILL.md`、`chapters/`、`concepts/`、`glossary.md`、`patterns.md`、`cheatsheet.md`、`quiz.md`、`flashcards.md`、`manifest.json`、`_work/`（过程产物）。
2. 写 `manifest.json`（schema 见 `references/templates.md` §10）；路径相对 manifest 所在目录。
3. 组装单书伴侣：
   ```bash
   python3 scripts/build_companion.py --manifest <root>/<书目录>/manifest.json \
       --out <root>/<书目录>/<slug>学习伴侣.html
   ```
4. 快速自检：浏览器打开伴侣，章节/测验/卡片/术语/搜索/深色可用。
   manifest 建议分两步写：先只填 `slug/title/book/chapters` 跑一次，确认页面能开、章节列表对得上，再补概念、测验、卡片。一次写全再调，出错很难定位是哪个字段。

**检查点**：每本书都有可独立打开的单文件 HTML；manifest 字段与 chapters/quizzes/cards 一致。

## Phase 6 — 整合总入口（核心）

目标：**一个 `index.html` 统一四类内容**——跨书总览、各书学习系统、单书伴侣入口、全局搜索。

1. 多书时先写 `00-跨书总览/`（单书可跳过，脚本会自动合成总览页）：
   - `README.md`：推荐学习顺序（按依赖与难度），每步给依据与能力里程碑；
   - `跨书概念映射表.md`：跨书概念 → 各书章节映射（对照真实 manifest，禁止拍脑袋）；
   - `综合检验建议.md`：跨书整合题 + 进阶路线。
2. 生成总入口：
   ```bash
   python3 scripts/build_handbook.py --root <点化学习系统目录>
   ```
   脚本自动完成：扫描各书目录与伴侣 HTML → 抽取内嵌数据 → 内链改写为 `#/book/<key>/...` → 测验 id 按章节加前缀去重 → 聚合「全部测验」页 → 修复 Mermaid 标签内的竖线语法 → 渲染跨书 Markdown → 输出 `index.html` 与 `index.md`。
   常用参数：`--order "01,02"` 指定书序；`--cross-dir 00-跨书总览`；`--label` 自定义标签。
3. 生成站点辅助文件（Pages 需要）：
   - `.nojekyll`（空文件，关闭 Jekyll，保证中文名与 `_` 目录原样托管）
   - `README.md`：交付与部署说明（模板见 `references/templates.md` §14）
4. 人工过一遍总入口：五类内容（跨书总览、四书、伴侣、搜索、进度）都要在。

**检查点**：`index.html` 单文件可离线打开；书切换与跨书页正常；`index.md` 链接有效。

## Phase 7 — 验证（交付前逐项执行）

**A. 总入口（必跑脚本）**
```bash
python3 scripts/verify_handbook.py --index <root>/index.html --chromium /usr/local/bin/chromium
```
覆盖：首页与书卡、跨书各页、每本书首末章、综合测验作答与解析、抽认卡翻转计数、术语过滤、全局搜索、进度跨刷新持久、深色模式、控制台零错误。

两件事要注意：Playwright 自带的浏览器包经常装不全，`--chromium` 指系统已有的 Chromium 最省事；失败项先分辨是产物的问题还是断言的问题——断言写死了初始状态（例如"应为 2/17"），前面的测试已经访问过章节就会显示 3/17，功能没坏。先在无痕窗口手点一遍再决定改哪边。

**B. 结构完整性**：知识库文件齐全（总纲/章节/概念/术语/模式/速查/测验/卡片/manifest）；manifest 与文件一一对应。

**C. 内容正确性**：抽 3~5 题核对答案与解析；术语首现即定义；图示语法有效（Mermaid 渲染或降级源码）；路径无死链。

**D. 交付包**：打包后**解压到独立临时目录**再冒烟测试 `index.html`（至少首页+每书一章+一个测验）。不能只测工作目录。

**E. 多书一致性**：章节无重复、概念已去重、路径统一、跨书映射与 manifest 一致。

发现错误：修产物 → 重跑组装 → 回到 A 复验；不要只改测试脚本。

## Phase 8 — 打包交付

1. 按 Phase 0 确认的模式打包：
   ```bash
   # 仅最终产物
   python3 scripts/package_delivery.py --root <点化学习系统目录> --out <root>.zip --mode final
   # 最终 + 中间产物
   python3 scripts/package_delivery.py --root <点化学习系统目录> --out <root>.zip --mode full
   ```
   脚本会确保 `.nojekyll`、生成/保留 `交付说明.md`（含目录结构、文件用途、使用方法、验证结论、部署步骤）。
2. 解压包到临时目录，跑 Phase 7-D 冒烟测试。
3. 交付时向用户给出：zip 路径、`index.html` 路径、说明 Markdown；如要部署 Pages，附三步命令与设置（见 `references/github-pages.md`）。

**检查点**：zip 可解压、包内 `index.html` 可开、说明完整、模式与用户要求一致。

## 多书/资料集合成规则

- 输入多本书：各自抽取结构与概念 → 合并概念清单（同名/同义去重并注明出处）→ 统一依赖图 → 按主题排学习路径 → 章节页标来源。
- 冲突口径：概念页用对比块列两种定义与适用场景，不强行统一。
- 目标为"吃透领域"：路径终点加跨书综合任务（进 `综合检验建议.md`）。
- 单书：仍然产出总入口（总览页=该书概览），保持"总览页学习"的统一形态。

## 合并多书时必然遇到的四个雷

按顺序处理，跳过一个后面就查不出来。

1. **内链没加前缀**。单书链接是 `#/chapter/ch01`，合并后必须变成 `#/book/<key>/chapter/ch01`。否则点了还在原地。
2. **测验 id 撞车**。每本书都从 `q01` 起，合并后所有选择器都指向第一题。按章节改写成 `ch01-q01`，`data-qid`、`input` 的 `name`、manifest 里的 id 三处同步改。
3. **"全部测验"页是空占位**。有的书这一页只写了一行"（无综合题）"。总入口里要按章把题拼起来重排，不能直接搬过去。
4. **Mermaid 语法在合并后才暴露**。各书单独看没问题，拼进总入口后标签里的 ` | ` 和半角括号开始报错。清洗只改方括号、花括号、边标签内部，`root((...))`、`A(...)` 这类形状语法不能碰。

## 时间花在哪

脚本部分很快：抽取、组装、验证、打包加起来几分钟。真正的时间在 Phase 2 和 Phase 3——逐章读原文、抽概念、写精讲。四本算法书里，写作占了绝大部分工时。想省这一步，出来的就是结构完整但没内容的东西。

所以排期时别把"脚本跑通"当成进度，它只是骨架立起来了。
